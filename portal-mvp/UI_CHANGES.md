# Blue-X v0.7.0 — UI 개선

## 주요 변경

- Blue-X / Trusted Data Transactions 브랜드 적용. BLUEMAP의 원본 로고와 B 심볼, 첨부 Gaia-X SVG의 색상·비율 유지.
- 첨부 Wizard의 인디고 #4F46E5, 바이올렛 #8B5CF6, 옅은 배경 #EEF2FF를 활용한 테마. 외부 폰트·CDN 없이 동작.
- 로그인·회원가입 화면 분리, 입력 검증 및 키보드 포커스 표시.
- 참여자 개요: 계정과 연결 조직 구분, 세션 만료·잔여 시간, 상태별 다음 작업, 검증→연결→제공/이용 진행 표시.
- 서비스 제공과 이용을 별도 메뉴로 구성. 서비스 이용은 서비스 찾기 / 내 이용 계약으로 분리.
- 계약·연결 상태와 국가 조건에 맞는 작업 버튼 표시. 최종 권한은 기존 서버 로직이 매 요청마다 판단.
- 계약 확인 안내, 계약 이후 주소 표시·복사·데이터 테스트. 원본 API 주소는 기존 접근 권한을 유지.
- 자격증명별 데모 연결 가능 여부, 현재 연결 사용 여부, 검사 상태별 건수, 문서별 상세 결과.
- 실패/확인 불가 검사가 있는 문서 상세는 상위 검증 결과를 펼쳤을 때 기본으로 열림.
- 제공 서비스 카드와 이용 참여자 목록. 기존 제공 서비스가 있으면 신규 등록 폼은 접어서 표시.
- 초기화·키 재발급을 개요의 접힌 관리 영역으로 이동. 파괴적 작업 확인 유지.
- 활동 로그의 기존 상세 정보·필터·페이지 이동·운영자 전체 조회 유지.
- 모바일 메뉴·카드·표 스크롤 대응. 시스템 정보 대화상자와 버전 표기.

## 실행·업데이트

기존과 같이 `python portal.py --port 8000`으로 실행합니다. 실행에는 Python 3.11 이상 및 requirements.txt의 의존성이 필요합니다.

`assets/` 폴더가 추가되었습니다. console.html만 옮기지 말고 프로젝트 파일과 assets/를 함께 배포하세요. Node.js와 프런트엔드 빌드 단계는 필요 없습니다.

기존 `data/` 폴더와 SQLite DB는 그대로 보존하세요. 이 배포 ZIP에는 계정·VC·테스트 DB가 없습니다. 기존 PORTAL_* 설정, API 경로, 접속 키, DB 스키마는 그대로 사용합니다. UI 개편으로 기존 계약이나 자격증명을 초기화하지 않습니다.

## 버전과 사양

- Blue-X 애플리케이션: 0.7.0
- 프로젝트 검증 프로필: loire-demo-v2 (이전 버전과 동일)
- 자격증명 환경: Loire / Non-production
- 설계 참고: Architecture Document 3.1, ICAM 25.11, Data Exchange Document 25.07

참고 사양과 실제 검증 프로필을 분리해 표시하며, 전체 사양 구현 또는 Gaia-X 적합성 인증을 의미하지 않습니다. Wizard의 2.3.0은 별도 도구 버전이므로 Blue-X 버전으로 표기하지 않습니다.

## 기존 파일

`dashboard.html`은 이전 검증기 화면의 보관 파일이며 현재 루트 경로는 `console.html`을 제공합니다. 데이터 검증 코드와 검증 정책은 수정하지 않았습니다.

## 검증 결과

- 기존 통합 테스트 26개 통과.
- Chromium에서 로그인 → VC 세션 연결 → 서비스 계약 → ping → 샘플 데이터 요청 → 서비스 등록을 확인.
- 자격증명 상세, 활동 로그, 운영자 화면, 시스템 정보 대화상자와 모바일 390px 화면을 확인.
- 테스트는 기존 테스트용 VC 검증 보고서 fixture 및 고정 샘플을 사용. 실제 VC의 암호 검증·외부 Weather API 연결을 새로 검증한 것은 아님.
- `previews/`의 화면은 테스트 계정·샘플 데이터로 촬영한 예시임. 실제 실행 시 사용자 계정과 데이터가 표시됨.
